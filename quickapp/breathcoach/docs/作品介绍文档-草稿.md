## 1、产品概述

**产品名称**：静息（breathcoach）

**一句话介绍**：持续监测腕上压力与心率，压力偏高时引导你完成科学节奏的呼吸训练，训练后展示前后对比并给出 AI 恢复建议。

**应用场景**：

- **职场高压人群的即时平复**：重要会议前、连续加班时，抬腕即可看到当前压力等级，60–80 秒跟随呼吸圆环完成一组 4-2-6 平复训练，无需掏出手机。
- **睡前助眠**：卧室场景下切换 4-7-8 助眠模式（吸 4s · 屏 7s · 呼 8s），呼气显著长于吸气，激活副交感神经帮助入睡。
- **解决的用户痛点**：现有智能手表健康能力普遍"只监测、不干预"——压力值偏高之后没有下文；而手机端冥想/呼吸类 App 需要主动打开手机、干扰强、依赖网络。本作品把手表的"常驻、被动感知"特性变成"感知即干预"的闭环。

**创新功能与体验亮点**：

1. **监测—干预—复盘完整闭环**：实时压力仪表盘（1Hz 刷新 + 等级变色圆环 + 脉搏涟漪）→ 双模式呼吸训练（圆环随节律缩放，squash & stretch 手感）→ 训练前后压力/心率对比（数字滚动动画）→ AI 生成个性化恢复建议。
2. **端侧 AI + 全环境降级架构**：AI 问答基于 openvela 端侧大模型能力（@system.velaclaw），采用软加载 + 4 秒超时兜底 + 关键词匹配本地建议的三级降级设计，端侧 AI 不可用时任何功能照常可用、任何环境演示不中断。
3. **液态玻璃视觉体系**：引擎不支持 backdrop-filter，我们用 Python 脚本离线预渲染肥皂泡虹彩/玻璃折射材质序列帧（8 帧循环轮播 + 半透明 tint 相位着色），在手表 GPU 限制下实现"液态玻璃"质感；材质生成脚本已随源码开源（docs/gen_*.py）。
4. **严肃的圆屏适配**：所有 UI 元素按"以圆心为圆心、半径约 215px 安全圆"布局，内容纵向总高按弦宽约束逐页算账（首页压缩至 398px、总结页 ~406px 适配 466 圆屏），AI 文案设 4~5 行硬上限防超长文本顶飞按钮。
5. **纯函数呼吸引擎**：呼吸相位推进与圆环尺寸计算抽象为独立纯函数模块（common/breathing.js），与 UI 解耦，便于测试与扩展新模式。

## 2、openvela 系统能力运用

**系统能力使用清单**：

| 能力 | 用法 |
| --- | --- |
| `service.health` | `subscribeSample` 实时订阅压力（dataType=9）与心率（dataType=0），首页 1Hz 刷新仪表盘；`getRecentSamples` 页面秒开即有数据；manifest 声明 `hapjs.permission.HEALTH` 与 background feature |
| `@system.velaclaw` | 端侧 AI 问答（训练总结建议 + AI 助手对话），读入当前压力/心率作为提问上下文 |
| `@system.router` / `@system.app` | 三页面路由与应用退出（本引擎 `@system.app` 导入为空对象，退出入口走 `$app.exit`） |
| `designWidth 466` | 按真实表盘分辨率设计，配合安全圆布局 |

**开发中遇到的引擎/工具链问题与改进建议**（完整 16 条见随作品提交的《Vela 模拟器踩坑记录》文档）：

1. `border-radius` 不支持百分比写法，`50%` 被按 px 处理 → 建议 CSS 层支持百分比圆角，或在开发阶段给出告警；
2. `border` 只写 width/color 不写 `border-style` 时边框整体静默不渲染 → 建议 border-style 缺省值为 solid 或构建期静态检查；
3. 模板 `onclick="fn('arg')"` 内联事件参数静默失效、无任何报错 → 建议工具链编译期校验内联表达式能力；
4. 模拟器 `setInterval` 触发频率偏高，按 tick 累计会导致动画节奏快数倍 → 我们改用真实时间戳推进；建议引擎对齐标准 setInterval 语义；
5. 响应式 data 上挂引擎对象疑似触发深层观测异常（训练页动画冻结）→ 建议文档明确响应式数据只放基本类型的约束；
6. 两份不同版本的 adb（IDE 扩展自带 vs SDK）会互杀 server，导致 IDE 预览 gRPC 粘性失败 → 建议 IDE 与 SDK 统一 adb 版本；
7. 模拟器 guest（goldfish/NuttX）偶发内核 backtrace 崩溃，与 App 无关，重启即可恢复且持久盘应用保留 → 建议 qemu 崩溃时 IDE 给出明确提示而非预览无限转圈。

**对模拟器数据回放的评价**：内置 `health_mock_publisher` 让初赛阶段完全不依赖真机即可开发、演示完整功能闭环，这个设计对参赛体验帮助很大，值得保留并向其他快应用品类推广。

## 3、硬件适配说明

**是否完成全新硬件平台适配或驱动开发**：否

本项目基于大赛官方 `vela-miwear-watch-5.0（开发者大赛）` 模拟器镜像与 goldfish 模拟器开发，未涉及芯片/开发板级驱动适配。应用按 watch 形态、466 圆屏规格设计，决赛阶段计划申请真机样机完成实机验证（健康传感器数据源由 mock 回放切换为真实采样，代码无需改动——数据访问已统一收敛在 service.health 封装层）。
