# Vela 模拟器踩坑记录 & 一次跑通指南

> 适用环境：Windows + AIoT IDE（D:\AIoT-IDE）+ vela-miwear-watch-5.0-beta 模拟器 + 静息（breathcoach）快应用
> 整理日期：2026-09-12（当天模拟器 guest 崩溃 2 次、预览黑屏、adb 互杀、训练页冻结各踩了一遍）

---

## 〇、先搞清楚 5 个东西，别再混淆

| 名字 | 是什么 | 画面从哪来 |
| --- | --- | --- |
| **Vela 模拟器（qemu）** | 真正的模拟器进程 `qemu-system-armel.exe`，guest 是 NuttX/miwear | 自己就能渲染（带 `-qt-hide-window` 时隐藏窗口） |
| **qemu 独立窗口** | 不加 `-qt-hide-window` 启动时弹出的表盘窗口 | 模拟器真实帧缓冲，**和 IDE 预览完全等价** |
| **IDE 右侧「VELA VIRTUAL DEVICE」面板** | IDE 的画面**镜像**，不是模拟器本体 | 必须先完成 IDE↔模拟器的调试握手（gRPC）才有画面，否则永远转圈 |
| **MuMu 模拟器** | 你机器上的安卓模拟器，和本项目无关 | 它会占用 adb 的 `emulator-5554`，别认错设备 |
| **adb（两份！）** | IDE 扩展自带一份 + .vela SDK 一份，**版本不同会互杀 server** | 见坑 4 |

关键认知：**应用能不能跑，只取决于 qemu 进程；IDE 右边面板黑屏 ≠ 应用没起来。**
判断应用活着的最可靠方法：`adb -s emulator-5556 shell "ps" | grep breath`。

## 一、今天的坑（症状 → 根因 → 处理 → 预防）

### 坑 1：模拟器 guest 内核崩溃，进程无声消失
- **症状**：模拟器/应用前一秒还在，几分钟后 adb 列表空了、qemu 进程没了、IDE 预览永远转圈。日志（qemu 控制台）里有 `sched_dumpstack: backtrace|...`。
- **根因**：goldfish guest 内核崩溃，与 App 代码无关（当天第一次崩溃发生在任何训练页操作之前）。
- **处理**：重启模拟器即可（见下文启动指南），数据盘 `.vvd` 里已安装的应用会保留（`pm install` 写的是持久盘）。
- **预防**：无（模拟器镜像本身的问题）。发现 adb devices 突然变空，先怀疑它崩了，直接重启。

### 坑 2：两份 adb 互杀 server → IDE 预览黑屏 / 设备消失
- **症状**：本来好好的，命令行跑了一次 adb 之后，IDE 的预览转圈、`adb devices` 变空、IDE 日志出现 `gRPC connection failed`。
- **根因**：IDE 扩展的 adb 和 `.vela\sdk` 下的 adb 版本不同，后启动的 server 会杀掉先前的，IDE 的设备监控全部断线，且 gRPC 通道进入粘性失败（重启会话才能恢复）。
- **处理**：杀掉所有 adb server 和 qemu，按启动指南让 IDE 全新拉一遍。
- **预防（重要）**：
  - 命令行只用这一份 adb：`C:\Users\LAINXIANG\.aiot-ide\extensions\vela.aiot-emulator-1.7.22\dist\bin\win\adb.exe`
  - IDE 正在调试时，**永远不要**在命令行跑另一份 adb，尤其不要 `adb kill-server`。

### 坑 3：IDE 右侧预览面板黑屏/转圈
- **症状**：面板只有表盘外壳 + 中心小转圈；同时右下角可能挂着「无法连接调试器」「已与调试服务断开连接」「gRPC connection failed」。
- **根因**：预览面板依赖 IDE 自己拉起的模拟器 + 调试握手成功。挂过死实例、或调试握手失败后，刷新按钮也救不回来。
- **处理**：不要纠结面板。看 qemu 独立窗口（手动启动时别加 `-qt-hide-window`），或直接 adb 验证进程。要救面板就按启动指南的「路线 A」完整走。

### 坑 4：IDE 点「调试」只构建、不推送不启动
- **症状**：AIoT Core 日志停在 `afterCompile: Check resource`，没有 Push/Install/am start。
- **根因**：IDE 的调试管线要先和模拟器建立连接；连接坏了它就默默停在那。
- **处理**：见启动指南。必要时走「路线 B」手动推送（100% 可靠）。

### 坑 5：MuMu 占用 `emulator-5554`，别认错设备
- **症状**：`adb devices` 里出现 emulator-5554，对它 `shell ps` 看到的是 Android（init/kthreadd），不是 NuttX。
- **根因**：那是 MuMu（安卓）。Vela 模拟器会顺延占用 `emulator-5556`。
- **处理/预防**：操作前先 `adb devices`，**Vela 的实例默认是 emulator-5556**（MuMu 关掉时才可能是 5554）。区分方法：`ps` 输出是 NuttX 风格（`FIFO/POLICY/Task`）才是 Vela。

### 坑 6：onclick 内联参数不生效（工具链限制）
- **症状**：模板里写 `onclick="setMode('sleep')"`，点击无任何反应，无报错。
- **根因**：aiot-toolkit 2.0.5 + 当前 Vela 引擎不支持内联事件参数。
- **处理**：改成一个参数一个方法（`setCalmMode` / `setSleepMode`），或 `data-*` 属性 + 事件对象取值。
- **预防**：本项目内一律用方法引用绑定，不写内联参数。

### 坑 7：把对象赋给响应式 data，疑似导致训练页动画冻结
- **症状**：训练页停留在某一帧不动（首页正常）。
- **根因**（高度怀疑）：`this.pattern = this._pattern`（含嵌套 phases 的对象）赋给 `private` 数据触发深层观测异常。
- **处理**：data 里只放字符串 `patternShort`，完整 pattern 只存在非响应式的 `this._pattern` 上。已改，待复验。
- **预防**：响应式 data 只放基本类型和纯展示字段；引擎对象一律走 `this._xxx` 非响应式成员。

### 坑 8：qemu 独立窗口的触摸坐标有偏移
- **症状**：看着点 A，实际命中的是下方 ~25px 的 B（当天实测：点「助眠」胶囊实际点到了下面的「开始呼吸训练」）。
- **处理**：先点一个已知结果的目标校准偏移量，再换算目标坐标；或优先在 IDE 预览面板里点（面板无此问题）。
- **预防**：给可点元素留大一点的命中区（胶囊这类小按钮尤甚）。

### 坑 9：Git Bash 会改写 adb shell 里的路径
- **症状**：`adb shell "pm install /data/app/xxx.rpk"` 报 `D:/Git/Git/data/app/...` 找不到。
- **根因**：MSYS 自动把 `/data/...` 转成 Windows 路径。
- **处理**：命令前加 `export MSYS_NO_PATHCONV=1`。

### 坑 10：IDE 无障碍（UIA）点「确定/复选框」经常无效
- **症状**：设备选择弹窗里，对 checkbox 发 AXPress 后仍显示「已选 0 项」。
- **处理**：改用屏幕坐标直接点复选框，看「已选 1 项」再点确定。

### 坑 11（顺带）：`.temp_breathcoach` 是临时目录，会被自动清理
- 构建产物最终在 `breathcoach/dist/com.vela.breathcoach.debug.1.0.0.rpk`，手动推送用这个。

### 坑 12：引擎不支持 `border-radius: 50%` 百分比写法
- **症状**：样式里写 `border-radius: 50%` 想画圆，实际渲染成圆角方块（边缘有平直段），无报错。
- **根因**：Vela 引擎的 CSS 不支持百分比圆角，值被按 px 处理（50% ≈ 50px）。
- **处理/预防**：圆角一律用 JS 算好 px 绑定到模板（如 `Math.round(Math.min(w, h) / 2)`），动态尺寸的元素每帧一起更新。

### 坑 13：`border` 只写 width/color 不写 `border-style` 时边框不渲染
- **症状**：`border-width` + `border-color` 都写了，但描边不显示，无报错。
- **根因**：border-style 缺省不是 solid，边框整体无效。
- **预防**：border 三件套（width/style/color）永远一起写。

### 坑 14：命令行可不依赖 IDE 直接出 rpk
- `npx aiot build`（工程目录下）即可完成构建+签名，产物自动从 `.temp_breathcoach/dist` 迁移回工程 `dist/`。
- 配合路线 B 的 adb 手动部署，改码→看效果的循环完全不需要打开 IDE。

### 坑 15：圆屏上"方形角落"里的元素不可见
- **症状**：元素放在 466x466 的四角（如左上角 22,22 处的返回按钮），模拟器上怎么都找不到。
- **根因**：角点到屏幕中心的距离（如 (44,44) 处约 267px）超过圆屏半径 233px，被表圈裁掉。
- **预防**：UI 元素必须放在以圆心为圆心、半径 ~215px 的安全圆内；左上 45° 方向的安全起点约在 (60,90)。内容纵向总高同理受"弦宽"约束。

### 坑 16：手表 IME 软键盘会盖掉半屏内容且难收起
- **症状**：`<input>` 聚焦后系统键盘从底部弹出，盖住大半个圆屏，且模拟器上没有可靠的收起手段。
- **预防**：手表端避免自由文字输入；交互用快捷指令（chips）替代。若必须输入，单独开输入页。

### 坑 17：目录重组/搬迁后 release 构建报"certification path"错误
- **症状**：`npx aiot release` 报 `The current mode is production, and there is a problem with the certification path`。
- **根因**：`sign/` 在 `.gitignore` 里，`git mv` 重组目录时只搬受跟踪文件，签名证书留在了旧位置。
- **处理**：把 `sign/{debug,release}` 整体移到新工程根目录下。
- **教训**：gitignore 的文件不属于 git，一切"以 git 为准"的搬家都不会带走它们。

### 坑 18：`pm uninstall` 可能静默失败，同版本覆盖安装也没保障
- **症状**：推了新 rpk、`pm install` 无报错、`am start` 进程也在，但跑的还是旧版本 UI。
- **根因**：卸载/安装环节存在静默失败（无回显即成功的假设不成立），同版本覆盖安装同样不可靠。
- **处理（可靠流程）**：① 版本号务必递增（versionName/versionCode）；② 卸载后**验证真的卸掉了**——`am start` 应当拉不起、`ps` 里进程为 0；③ 再 push + install + start，每步用 ps 验证。
- **教训**：这类 NSH 命令无回显不等于成功，"装上了"必须以可观测证据（版本递增、行为变化）为准。

### 坑 19：换资源后 UI 不变——引擎有跨安装的内存图片缓存
- **症状**：替换 `src/common/images/` 下的贴图并重装应用（甚至升版本号）后，UI 渲染的仍是旧图。
- **排查**：rpk 拆包比对 md5 一致 + 设备 `/data/app/<pkg>/` 内资源 md5 一致 + 进程重启过，但画面依旧 → 缓存在引擎/媒体服务内存里，与安装包无关。
- **处理**：**重启模拟器**（杀 qemu 重启）即可，重启后渲染新图。
- **教训**：调视觉时"改了没效果"先重启模拟器再怀疑人生；验证链条 = rpk 内容 → 设备文件 → 渲染结果，逐层用字节证据说话。

## 二、一次跑通指南

### 路线 A（首选）：IDE 全流程

> 适用：IDE 状态正常、想用右侧预览面板/断点调试时。

1. **清场**（每次开机后第一次跑之前必做；平时跳过）
   ```powershell
   taskkill /F /IM qemu-system-armel.exe        # 杀残留模拟器（没有就忽略报错）
   taskkill /F /IM "AIoT IDE.exe"               # 彻底关 IDE
   del /q "C:\Users\LAINXIANG\.vela\sessions\broker-window-*.json"   # 清死会话记录
   ```
   再杀一次所有 adb server（保证干净）：任务管理器结束所有 adb.exe。
   ⚠️ 此步骤之外，全程不要再碰任何 adb。
2. **启动 IDE 并打开项目**：等右下角「当前项目可以正常启动」四个 ✅。
3. **选择设备**：顶栏「选择设备」→ 勾选 `Vela_Virtual_Device`（绿点=可用）→「确定」。角标应显示 `1`。
4. **点顶栏「调试」**（注意是项目工具栏那个，不是左侧 VS Code 的「运行和调试」面板）。
5. **看 AIoT Core 日志确认节奏**（IDE 底部「输出 → AIoT Core」）：
   - `start build` → `webpack complete` → `Project build and generate files`（约 5–10s）
   - 紧接着 5–10 秒内应出现：`Push result` → `Install ... successfully` → `am start com.vela.breathcoach`
   - 模拟器首次冷启动会先 boot 40–60 秒才推送，属正常，别手点第二下。
6. **验收**：IDE 右侧预览面板亮起首页；或 `adb devices` 后 `shell "ps"` 里有 `com.vela.breathcoach`。
7. 功能验证清单见第四节。

> 路线 A 走到第 5 步如果卡在 Check resource 不推送 → 模拟器八成崩了或没被 IDE 拉起来，直接转路线 B。

### 路线 B（兜底，100% 可靠）：手动拉模拟器 + 手动部署

> 适用：IDE 调试管线抽风（预览黑屏/只构建不推送）、或只想快速看真机画面时。
> 此路线用 qemu 独立窗口看画面，放弃 IDE 右侧面板。

1. **杀残留**：`taskkill /F /IM qemu-system-armel.exe`（忽略不存在的报错）。
2. **启动模拟器**（Git Bash；关键是 **去掉 `-qt-hide-window`** 才有可见窗口）：
   ```bash
   cd "C:\Users\LAINXIANG\.vela\vvd" && \
   ANDROID_AVD_HOME="C:\Users\LAINXIANG\.vela\vvd" \
   "C:\Users\LAINXIANG\.vela\sdk\emulator\windows-x86_64\emulator.exe" \
     -vela -avd Vela_Virtual_Device -show-kernel \
     -qemu -device virtio-snd,bus=virtio-mmio-bus.2 -allow-host-audio -semihosting -smp 2 \
     > /tmp/emu.log 2>&1 &
   ```
   （`-show-kernel` 会把 guest 内核日志打进 /tmp/emu.log，排查崩溃全靠它。）
   完整原始参数备份在：`C:\Users\LAINXIANG\.vela\vvd\Vela_Virtual_Device.vvd\emu-launch-params.txt`
3. **等 boot 完成**（40–60 秒）：
   ```bash
   ADB="C:\Users\LAINXIANG\.aiot-ide\extensions\vela.aiot-emulator-1.7.22\dist\bin\win\adb.exe"
   "$ADB" devices          # 应看到 emulator-5556（MuMu 开着时 5554 是它，别认错）
   "$ADB" -s emulator-5556 shell "ps" | grep health_mock   # 看到 = guest 起来了
   ```
4. **构建 rpk**：IDE 里点一下「调试」让它构建（看日志出现 `Project build and generate files` 即可，不推送也没关系）。
   产物：`breathcoach\dist\com.vela.breathcoach.debug.1.0.0.rpk`
5. **手动部署**（记得 `MSYS_NO_PATHCONV=1`）：
   ```bash
   export MSYS_NO_PATHCONV=1
   "$ADB" -s emulator-5556 push "C:\Users\LAINXIANG\Desktop\小米\breathcoach\dist\com.vela.breathcoach.debug.1.0.0.rpk" /data/app/com.vela.breathcoach.rpk
   "$ADB" -s emulator-5556 shell "pm install /data/app/com.vela.breathcoach.rpk"
   "$ADB" -s emulator-5556 shell "am start com.vela.breathcoach"
   ```
6. **验收**：qemu 表盘窗口亮出首页。改了代码后重复第 4–5 步（先 `am stop` 再 push 也行，直接覆盖安装即可）。

### 崩溃后如何恢复

- 症状：qemu 窗口消失 / `adb devices` 里 5556 没了 / 画面冻结后整个窗口没了。
- 处理：`taskkill /F /IM qemu-system-armel.exe` → 重跑路线 B 第 2 步 → **应用还在盘上，直接 `am start` 即可**，不用重装。
- 崩溃证据在 /tmp/emu.log（或 IDE 日志 `3-Vela_Virtual_Device.log`），特征是 `sched_dumpstack: backtrace`。

## 三、排障速查表

| 症状 | 先查 | 结论 |
| --- | --- | --- |
| 预览面板转圈 | `adb devices` 有没有 5556 | 没有 = qemu 崩了，重启；有 = 调试握手没成，转路线 B |
| 点调试只构建不推送 | AIoT Core 日志最后 3 行 | 停在 Check resource = 连接问题，转路线 B 第 5 步手动推 |
| `adb: device not found` | `adb devices` 全表 | 5556 不在 = qemu 崩；5554 在 = 那是 MuMu，别认错 |
| 应用进程在但画面全黑 | qemu 窗口是否在 | guest 屏幕休眠/窗口被遮挡，点一下表盘或调窗口到前台 |
| 训练页冻住 | /tmp/emu.log 有无 backtrace | 有 = guest 崩，重启模拟器；无 = App JS 问题，查最近改动 |
| IDE 预览/UIA 全部失灵 | 任务管理器数 AIoT IDE.exe | 重启 IDE（状态机可能已坏），必要时删 `.vela/sessions/broker-window-*.json` |

## 四、功能验收清单（每次改版后过一遍）

1. 首页：压力圆环（数值+等级变色）、心率、AI 入口、趋势柱状图滚动
2. 模式胶囊：点「助眠 4-7-8」→ 高亮切换到紫底、主按钮变「开始助眠训练」
3. 平复训练：进入训练页，顶部「吸 4 · 屏 2 · 呼 6」，底部「4-2-6 平复 · 共 6 组 · 约 72 秒」，圆环按 4s/2s/6s 缩放
4. 助眠训练：同上，应为「4-7-8 助眠 · 共 4 组 · 约 76 秒」，呼气 8 秒明显更长
5. 训练总结：前后压力对比 + 数字滚动 + AI 建议（本地降级模式）
6. 回首页趋势柱仍在滚动

> 模拟器内置 `health_mock_publisher` 回放健康数据，首页有数是正常的，不需要真机。
